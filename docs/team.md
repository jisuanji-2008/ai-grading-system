## 崔鹏宇 · 制作

**负责的文件**（评审时能当场打开讲设计）：

- `server/grader.js` — 判分 Prompt 的设计与三轮迭代；JSON 输出校验（缺条补 0、越界夹取、总分重算）；**证据校验**：每条理由必须逐字引用学生原文、不得跨条复用，对不上直接判 0（这是把 MAE 从 2.33 降到 0.67 的关键改动）
- `server/db.js` — SQLite 表结构（题目 / 答卷 / 判分记录），判分异步落库、失败可重批
- `server/config.js` — 多服务商预设（DeepSeek / 智谱 / 通义…），Key 只走环境变量
- `public/` — 出题台 / 学生作答 / 批改台 / 评测报告 / 人工计时五个页面（无框架纯 DOM），分数环、逐条得分条、原文高亮
- `scripts/` — 端到端评测（MAE / ±1 分率 / 相关系数 / 耗时）、Key 体检、命令行计时
- `server/index.js` 的 `/api/timer`、`/api/human-timing` — 网页内人工计时，提交后自动重算报告

**能答的问题**：为什么 Prompt 要强制引用原文？为什么换更弱的模型会偏松？评测指标怎么算的？证据校验具体怎么实现？

## 付禹棋 · 解说

**负责的部分**（同样能指出来、说清楚）：

- **演示录屏（B 站）** — 按 `docs/demo-script.md` 走完核心流程，讲清"换一份答案，AI 的分数和理由怎么变"，最后汇报测试数据。视频本身就是可验收的成果
- **人工基准打分** — 在「人工计时」页逐份批改 6 份答案（`eval/answers.json` 里的人工分即由此产生），产出 `eval/human-timing.json`，这是报告里"AI 快多少倍"的数据来源
- **评测结论的解读** — `eval/report.md`、README 里的"结果与局限"，能讲明白 MAE 0.67 分、±1 分率 67%、r=0.96 各自意味着什么，以及样本只有 6 份、单一评阅人带来的局限
- **测试反馈** — 提出"AI 给 4 分是不是偏高""理由引用的原文对不对"这类质疑，直接推动了 v1 → v2 的证据校验改造

**能答的问题**：人工基准怎么保证公平（互不参考、逐条给分、计时页不显示 AI 分）？为什么保留教师确认环节？0.67 分的误差在实际阅卷中算什么水平？
