## 甲：后端与判分引擎

**负责的文件**（能当场打开讲设计）：

- `server/grader.js` — 判分 Prompt 的设计与三轮迭代；JSON 输出校验（缺条补 0、越界夹取、总分重算）；**证据校验**：每条理由必须逐字引用学生原文、不得跨条复用，对不上直接判 0（这是把 MAE 从 2.33 降到 0.67 的关键改动）
- `server/db.js` — SQLite 表结构（题目 / 答卷 / 判分记录），判分异步落库、失败标记可重批
- `server/config.js` — 多服务商预设（DeepSeek / 智谱 / 通义…），Key 只走环境变量
- `scripts/evaluate.mjs` — 端到端评测：起服务、跑 6 份答案、算 MAE / ±1 分率 / 相关系数 / 耗时，生成报告
- `scripts/check-key.mjs` — Key 体检命令

**现场可答的问题**：为什么 Prompt 要强制引用原文？为什么换更弱的模型会偏松？评测指标怎么算的？

## 乙：前端与评测验证

**负责的文件**（能当场打开讲设计）：

- `public/` 全部 — 出题台 / 学生作答 / 批改台 / 评测报告四个页面（无框架纯 DOM），分数环、逐条得分条、原文高亮
- 「批改台」的教师复核流程 — AI 分仅供参考，教师改分 + 写备注 + 确认后才算最终成绩
- 「人工计时」页 — 逐份批改自动计时，提交后自动重算评测报告（`server/index.js` 的 `/api/timer`、`/api/human-timing` 接口）
- `eval/answers.json` — 6 份测试答案的编写，以及**人工基准分**：按评分标准逐条打分（这正是对比数据的"人工"一侧）
- 演示录屏（B 站）与 `docs/demo-script.md`

**现场可答的问题**：人工基准怎么保证公平（互不参考、逐条给分）？为什么保留教师确认环节？计时口径是什么？
